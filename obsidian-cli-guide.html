1Obsidian CLI とは何か

CLI は Command Line Interface の略で、画面のボタンやメニューの代わりに、文字のコマンドで操作する方法です。 Obsidian CLI を使うと、「今日の日記に 1 行追記する」「ノートを検索する」「タグの一覧を出す」といった操作を、 PowerShell などのターミナルから実行できます。 2026 年 2 月に、 Obsidian 1.12 系の公式機能として加わりました [2] 。

何が嬉しいかというと、次の三つです。

  • 操作を文字で書けるので、スクリプトにして繰り返せる（自動化）。
  • 他のツール（ jq や Claude Code など）と組み合わせられる。
  • ノートの移動や名前変更で、リンクが壊れないよう Obsidian 自身に処理させられる。
最も大事な前提
CLI は、起動中の Obsidian アプリに命令を送る仕組みです。アプリを使わずにファイルだけを直接触るものではありません。 Obsidian が起動していなければ、最初のコマンドで Obsidian が自動的に起動します [1] 。パソコン専用で、スマートフォン版にはありません。
旧来、サードパーティ製の同名ツール（ npm 版の obsidian-cli ）もありました。これは別物です。このガイドが扱うのは、 Obsidian 本体に含まれる公式の CLI です。

2準備する

2.1 有効化の手順

最初に、仕組みの説明をします。 CLI の有効化は、「 Obsidian が、ターミナルから obsidian と打てるように、自分の場所を PATH （コマンドの探索先の一覧）に登録する」作業です。登録は Obsidian の設定画面から行います。

  1. Obsidian のバージョンを確認し、インストーラ版 1.12.7 以降にする。古ければ公式サイトから入れ直す [1] 。
  2. Obsidian の「設定」を開き、「 Obsidian について」へ進む。
  3. 「コマンドラインインターフェース」（ Command line interface ）をオンにする。
  4. 表示される案内に従って、登録を完了する。
  5. 開いているターミナルをすべて閉じ、新しく開き直す（ PATH の変更は、新しいターミナルから有効になる）。
OS登録で起きること
WindowsObsidian.exe と同じ場所にある Obsidian.com （ターミナル用の取り次ぎ役）が使われ、ユーザーの PATH に追加される。
Mac/usr/local/bin/obsidian に実体への近道（シンボリックリンク）が作られる。管理者の承認を求められる。
Linux~/.local/bin/obsidian にコピーされる。この場所を PATH に入れておく必要がある。
Windows では、管理者として開いた PowerShell から実行すると、出力が空のまま何も起きないことがあるという報告があります [2] 。ふつうに開いた PowerShell を使ってください。

2.2 動作確認

確認は、「何も壊さない、読むだけのコマンド」で行います。 Obsidian を起動した状態で、新しい PowerShell に次を打ちます。

obsidian version
obsidian help

obsidian version でバージョンが表示され、 obsidian help でコマンドの一覧が出れば成功です。

2.3 うまくいかないとき

症状確かめること
設定にスイッチが見当たらないインストーラ版が古い可能性がある。公式サイトから最新版を入れ直す。
obsidian が見つからないと言われるターミナルを開き直したか。 Windows なら新しい PowerShell で試す。更新前の版から上げた場合は、設定のスイッチをいったんオフにしてオンに戻す。
何も表示されない（ Windows ）管理者権限のターミナルを避ける。 Obsidian が起動しているかも見る。
obsidian version が obsidian-cli vX.Y.Z と出る旧来のサードパーティ製ツールを呼んでいる。公式の CLI ではない。
Mac で近道がないsudo ln -sf /Applications/Obsidian.app/Contents/MacOS/obsidian-cli /usr/local/bin/obsidian で手動作成する [1] 。

3コマンドの書き方の決まり

コマンドの形は、いつも同じです。一度覚えれば、どのコマンドにも通用します。

obsidian [vault=Vault名] コマンド名 [パラメータ=値 ...] [フラグ ...]
用語意味例
パラメータ名前=値 の形で値を渡す。値に空白があるときは引用符で囲む。query="meeting notes"
フラグ値を持たない単語。書けばオン、書かなければオフ。open ・ overwrite
vault=操作する Vault を指定する。指定するときは、必ず最初のパラメータにする。obsidian vault=Notes daily
file=ノートを名前で指定する。ウィキリンクと同じ解決の仕方で、パスも拡張子も要らない。file=Recipe
path=Vault の最上位からの正確なパスで指定する。path=Templates/Recipe.md
改行・タブ内容の中の改行は \n 、タブは \t と書く。content="1行目\n2行目"
--copy出力をクリップボードにも送る。obsidian read --copy

file= も path= も書かなかった場合は、いま Obsidian で開いているノート（アクティブなノート）が対象になります [1] 。意図しないノートに書き込まないよう、書き込み系では file= か path= を明示する習慣をお勧めします。

各コマンドの細かい指定は、 obsidian help コマンド名 で見られます [2] 。

対話モード（ TUI ）

引数なしで obsidian とだけ打つと、対話画面（ TUI ）が開きます。ここでは先頭の obsidian を省いてコマンドを打てます。

キー働き
Tabコマンド名の補完
Ctrl+R過去に打ったコマンドの逆引き検索
Ctrl+L画面を消す
Ctrl+C ／ Ctrl+D終了

TUI の中で Vault を切り替えるには、 vault:open 名前 を使います。

4最初の一歩 : 読むだけのコマンドから

小さく試して、納得しながら進める手順にしてあります。ステップごとに結果を確かめてから、次へ進んでください。

書き込み系を試す前に
書き込み・削除をするコマンドは、最初は大切な Vault では試さず、練習用の空の Vault で試してください。 Obsidian 側に履歴（ファイル復元）の仕組みはありますが、まず安全な場所で挙動を見るのが確実です。

4.1 ステップ 1 : 読むだけ

理由 : 読むだけのコマンドは、ノートを変更しません。仕組みを覚える最初の練習に向いています。

obsidian vaults
obsidian tags counts
obsidian search query="会議" | Sort-Object
obsidian read file=Recipe
obsidian properties
  • vaults は、 Obsidian が知っている Vault の一覧を出します。 verbose を付けると、場所（パス）も出ます。どの Vault が対象になるかを、最初に確かめられます。
  • tags counts は、タグごとの使用数を出します。
  • search query= は、該当するノートのパスを出します。本文の一致行まで見たいときは search:context を使います [2] 。
  • read file= は、指定したノートの内容を出力します。
  • properties は、 Vault のプロパティ（ノートの属性）を一覧します。

4.2 ステップ 2 : 書き込みを試す

理由 : 書き込みは、自動化の中心的な使い道です。ここからは練習用の Vault で試します。

obsidian daily:append content="- [ ] 牛乳を買う"
obsidian create name="練習ノート" content="こんにちは"
obsidian append file="練習ノート" content="追記の1行"
obsidian read file="練習ノート"
  • daily:append は、今日のデイリーノートの末尾に追記します。ノートを開いていなくても実行できます。
  • create は、新しいノートを作ります。同名のノートがあるときに上書きしたければ、フラグ overwrite を付けます。作成後に開きたければ open を付けます。
  • append は、指定したノートの末尾に追記します。
日本語や記号を含む引数は、 PowerShell の引用符の扱いで思いどおりに渡らないことがあります。うまくいかないときは、まず半角英数字だけで試し、結果を read で読み戻して確かめてください。

6使い道の例

ここからは応用です。どれも、ステップ 1 ・ 2 が動いてから試してください。

例 1 : どこからでも一言メモを取る

PowerShell の関数にしておくと、ターミナルで memo 買い物に行く と打つだけで、デイリーノートにタスクが追記されます。 PowerShell のプロファイルに書けば、毎回使えます。

function memo {
    obsidian daily:append content="- [ ] $($args -join ' ')"
}

例 2 : Vault の健康診断

どこからもリンクされていないノートや、リンク先が存在しないリンクを洗い出せます。定期的に実行して、整理の手がかりにします。

obsidian orphans
obsidian unresolved
obsidian tags counts

例 3 : 出力を他のツールへ渡す

一部のコマンドは format=json で JSON を出力できます [2] 。 jq などに渡せば、集計や加工に使えます。

obsidian search query="TODO" format=json

例 4 : Claude Code などの AI エージェントに任せる

エージェントは、ターミナルのコマンドを打てます。 CLI があれば、「この Vault でリンク切れを調べて」「このタグのノートを一覧して」といった作業を、 Obsidian 本体の処理を通して任せられます。ただし、書き込み・削除・移動を任せるときは、最初は練習用の Vault で試してください。

7知っておく注意点

注意点内容
Obsidian の起動が必要アプリを動かさずに使う（ヘッドレス）ことはできない。閉じていれば、最初のコマンドで起動する。
終了コードは常に 0失敗しても、終了コード（ $LASTEXITCODE ）は 0 のまま。エラーは出力の文字から判断する [2] 。
書き込みの確認成功と表示されても、変更されていないことがあるという報告がある。大事な書き込みは read で読み戻す。
一括処理は不向き1 回ごとに約 1 秒かかるとされる。大量のファイルを処理するなら、ファイルを直接扱う方が速い。
並列実行を避けるmove や eval を同時に走らせると、衝突することがある。
eval は強力プラグインと同じ権限でアプリ内のコードを実行する。特に AI が書いたコードは、中身を読んでから実行する。
複数の Vault既定の対象は、操作中の Vault か、現在のフォルダに対応する Vault 。取り違えを防ぐには vault= を明示する。
削除delete は既定でゴミ箱へ送る。完全に削除するオプションもあるため、実行前に obsidian help delete で確認する。

8次に進むには

  1. この文書の 4 章を、練習用の Vault で一通り試す。
  2. obsidian help の一覧から、自分の使い方に合いそうなコマンドを三つ選び、 obsidian help コマンド名 で詳細を読む。
  3. 例 1 の memo のように、よく使う操作を関数にする。
  4. 慣れたら、スクリプトやタスクスケジューラ（ Mac は cron や launchd ）で定期実行する。

疑問が出たら、実際に打ったコマンドと出力を持ってきてください。一緒に確かめながら進められます。

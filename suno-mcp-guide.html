1. 全体像

1.1 この手順書でできること、できないこと

この手順書は、 Claude と Suno のアカウントを持つ人が、 Claude の会話から Suno に曲づくりを頼めるようにするための手順をまとめたものである。 Claude と Suno の各プランの条件は、第 3 章に書く。 Suno は、 AI で曲をつくるサービスである。 Suno 自身が、 Claude などの AI アシスタントとつなぐための公式の接続口「 Suno MCP (Beta)」を提供している。 [1][2]

つながると、 Suno の公式ページによれば、次のことを AI アシスタントとの会話から頼めるようになる。 [1]

  • 文章による説明から曲をつくる(歌詞とスタイルは AI が書く)。
  • ボイスメモなどのアップロードした音声から、曲をつくる。
  • ライブラリにある曲の、カバー・マッシュアップ・延長をつくる。
  • 保存してある Suno Voices(歌声の設定)を、曲に使う。

本書が手順を詳しく書くのは、このうち「文章による説明から曲をつくる」だけである。ほかの機能は、紹介にとどめる。

範囲外 : MV(ミュージックビデオ)などの映像づくり。元の投稿の投稿者は、同じ会話で映像も頼み、 57 秒の MV にしたと報告している。 [11] しかし、投稿には映像をどの道具で作ったかが書かれていない。 Suno の公式資料にも、 Suno MCP で映像をつくる方法は見当たらなかった。公式資料で裏付けの取れる方法が確認できなかったため、本書は MV の章を設けない。

1.2 前提と注意

  • 実機では未検証である。冒頭に書いたとおり、本書は公式資料の読解に基づく。
  • ベータ版である。 Suno MCP の名称に「 Beta 」が付いている。 [2] 手順や画面の名前は、今後変わりうる。
  • 資料の取得日は 2026-10-31 である。メニュー名・コマンド・プランの条件のように変わりやすい情報は、各所に書いた公式ページで最新の内容を確かめてほしい。
  • 所要時間の目安は書かない。裏付けのある所要時間を、公式資料から得られなかったためである。
  • 画面の写真は載せない。メニューやボタンの名前は、公式資料にある文言を引用する。

1.3 完成までの流れ

全体は五つの段階に分かれる。最初に準備を整え、次に自分に合う経路を選び、接続し、つながったことを確かめてから、曲をつくる。

2. MCP とは

2.1 一言でいうと

MCP(Model Context Protocol)は、 AI と外部のサービスをつなぐための共通の取り決めである。 MCP の公式サイトは、 MCP を「 AI アプリケーションを外部システムにつなぐための、オープンソースの標準」と説明している。 [5]

同じ公式サイトは、 USB-C の差し込み口にたとえている。 USB-C が電子機器をつなぐ共通の形を決めているように、 MCP は AI アプリを外部のシステムにつなぐ共通の形を決める、という説明である。 [5]

このたとえが当てはまらない点。 USB-C は、差し込めば機器が動く。 MCP の接続は、差し込むだけでは終わらない。つなぐ先の URL を登録し、 Suno にサインインして、アクセスを承認する手順が要る。 [1] また、 USB-C のケーブルは機器を勝手に操作しないが、 MCP でつないだ AI は、利用者の代わりに操作を行う。この違いが、第 9 章の安全の話につながる。

2.2 この手順書の登場人物

名前役割

Suno曲をつくるサービス。つくった曲は Suno のライブラリに保存される。 [3]

2.3 MCP でできるようになること、起こりうること

MCP の公式サイトは、 MCP によって AI が「必要に応じて、利用者のデータにアクセスし、利用者に代わって行動できる」ようになると述べている。 [5] 便利さの裏返しとして、つないだ先が信頼できないものだと、 AI が意図しない動きをさせられるおそれがある。 Anthropic の資料は、悪意のある MCP サーバーが、 Claude に意図しない行動をさせる隠れた指示を含むことがある、と警告している。 [7] 対策は第 9 章に書く。

3. 事前準備

3.1 Suno のアカウント

Suno のアカウントが要る。 Suno の FAQ は、「 Suno MCP (Beta) は、無料のプランを含む、すべての Suno プランで使える」という趣旨で答えている。 [3] ただし、曲をつくるとクレジット(曲づくりに使う利用枠)を消費する。 FAQ は「音楽をつくるとき、プランに応じたクレジットを使う」という趣旨で説明している。 [3]

プランの確かめ方。 suno.com にサインインし、アカウントや料金プランを表示する画面で、現在のプラン名と、残りのクレジットを見る(作成者の案内)。画面の名前は版によって異なる場合がある。見つからないときは、 Suno の公式の案内を確認してほしい。残りのクレジットは、 AI ツールに尋ねる方法もある。 [1]

3.2 Claude のアカウント

Claude のアカウントが要る。 Claude アプリにカスタムコネクタ(自分で接続先の URL を登録するコネクタ)を追加できるのは、 Free から Enterprise までのプランである。ただし Free は、カスタムコネクタが一つまでである。 [7] ほかのコネクタを入れているときは、空きがあるかを確かめる。個別のプラン名ごとの対応は、資料で確認できなかった(要確認)。

ターミナルで使う Claude Code(経路 B )は、 Claude の有料プラン(Pro ・ Max ・ Ultra ・ Team ・ Enterprise)か、 Claude Console(事前に支払ったクレジットで API を使う形のアカウント。作成者の補足)のアカウントなどでログインする。 [8] この資料の列挙に Free は見当たらなかったが、 Free で使えないと言い切れるかは確認できていない(要確認)。

プランの確かめ方。 Claude アプリの設定のうち、アカウントやプランの情報を表示する画面で、現在のプラン名を見る。画面の名前は版によって異なる場合がある(作成者の案内)。

Team と Enterprise では、カスタムコネクタを組織に追加できるのは、所有者(Owner など)に限られる。 [7] 自分が所有者でないときは、所有者に依頼する必要がある。

3.3 使う道具

  • Claude アプリ : 経路 A で使う。
  • ターミナル : 経路 B だけで使う。コマンド(文字で入力する命令)を打ち込む窓である。 Windows では PowerShell 7 、 Mac では zsh が動くターミナルを使う。本書では、ターミナルを「開く」ことはできる前提で書く。

4. 経路の選び方

4.1 三つの経路の比較

Claude に Suno をつなぐ経路は、本書では三つに分ける。経路 A-1 と A-2 は、画面の操作でつなぐ。経路 B は、ターミナルのコマンドでつなぐ。

経路操作の場所必要なもの注意点
A-1 : Claude アプリのカスタムコネクタClaude アプリの Customize > ConnectorsClaude のアカウント(Free でも一つまで可)。 [7]Team と Enterprise は、所有者が先に追加する。 [7]
A-2 : Claude アプリの Code タブCode タブの入力欄の横の「 + 」Code タブを使える Claude のアカウント。必要なプランは、資料で確認できなかった。コネクタの項目は WSL のセッションでは使えない。 [9]

4.2 選ぶ目安

ターミナルを使ったことがなければ、経路 A-1 から始めることをおすすめする。画面の操作だけで進められ、コマンドを打つ必要がないためである。これは作成者の推奨であり、公式資料の記述ではない。

ターミナルに慣れている人や、 Claude Code をすでに使っている人は、経路 B でもよい。 Suno の公式ページは、 Claude Code 向けに claude mcp add のコマンドを案内している。 [1]

4.3 元の投稿の方法について

元の投稿の投稿者は、 Claude アプリの Code タブで「 Suno の MCP をつないで」と送ると、 Claude が Suno の公式ページを読み、コマンドを実行し、接続の確認まで済ませたと報告している。 [11] これは投稿者の報告であり、本書は再現を確かめていない。投稿には、読まれた URL も、実行されたコマンドも書かれていない。

この方法は、本書の本流には入れない。 Claude にコマンドを実行させる方法なので、内容を確かめずに許可すると危険があるためである。この方法を試すときに確かめるべきことは、第 9 章の 9.2 に書く。

5. 接続の手順

経路ごとに、選んだ経路の節だけを読めばよい。各ステップには「何のために」「操作」「うまくいったとき」「うまくいかないとき」の四つを書く。画面の操作は、 Windows でも Mac でも、アプリの同じ画面で行うと想定している(これは作成者の解釈である)。

各ステップの「うまくいったとき」のうち、出典の脚注が付いていない表示は、公式資料から想定した内容(作成者の解釈)であり、実機では確認していない。実際の表示と違うことがある。

5.1 経路 A-1 : Claude アプリのカスタムコネクタ

この節は、経路 A-1 を選んだ人向けである。 Anthropic の資料が Pro と Max の個人プランの手順として示すものを書く。 [7] Free で同じ手順になるかは、確認できなかった(要確認)。 Team と Enterprise では、先に所有者が「 Organization settings > Connectors 」から追加する。所有者が追加したあと、メンバーは「 Customize > Connectors 」で、そのコネクタの「 Connect 」を選ぶ。 [7]

ステップ A1-1 : コネクタの画面を開く

何のために
コネクタ(外部サービスとの接続)を管理する画面に移るため。カスタムコネクタは、この画面から追加する。

操作
Claude アプリで「 Customize 」を開き、「 Connectors 」を選ぶ。 [7]

うまくいったとき
コネクタを管理する画面が開くと想定される(作成者の解釈。未確認)。

うまくいかないとき
メニューの名前は版によって異なる場合がある。見つからないときは、 Claude の公式ヘルプ Get started with custom connectors using remote MCP を確認する。 [7]

ステップ A1-2 : Suno をカスタムコネクタとして追加する

何のために
Suno の接続口の URL を、 Claude に登録するため。 Suno は Claude の標準の一覧に自動では出ないことがあり、その場合はカスタムコネクタとして追加する。 [3]

操作
次の順に行う。 [7][2]

  1. 「 + Add 」を選び、「 Add custom connector 」を選ぶ。
  2. 名前の欄に Suno と入力する。
  3. サーバーの URL の欄に、次の URL を入力する。
https://api.suno.com/mcp
  1. 「 Continue 」を選ぶ。
  2. 認証の設定が表示されたら、内容を確かめて「 Continue 」を選ぶ。 Anthropic の資料によれば、この画面には「 Authentication 」(選択肢は「 Sign in now 」「 Sign in when needed 」「 No sign in 」)、「 OAuth client 」、「 Request headers 」の欄がある。 [7] 「 OAuth client 」は Claude が自分をどう名乗るかの設定、「 Request headers 」は API キーなどの固定の認証情報を付ける欄である(これは資料の説明からの作成者の解釈)。 Suno の公式ガイドは、これらの欄に触れていない。 [2] どの選択肢が Suno に適するかは、公式資料で確認できなかった。 Suno は、サインインして承認する方式で、 API キーは要らない。 [1] したがって、「 No sign in 」を選ばず、画面に表示された内容を自分では変えないことをおすすめする(作成者の推奨)。
  3. 「 Add 」を選ぶ。

URL は、一字一句そのまま入力する。似た名前の別の URL を使ってはならない(第 9 章を参照)。

うまくいったとき
コネクタの一覧に「 Suno 」が加わると想定される(作成者の解釈。未確認)。

うまくいかないとき
Suno の FAQ は、つながらないときは、 MCP の URL(https://api.suno.com/mcp)が正しいことと、 Suno のサインインと承認が終わっていることを、見直すよう案内している。 [3] コネクタの内容を直したいときは、いったん削除してから、直した内容で追加し直す必要がある。 [7]

ステップ A1-3 : Suno にサインインして承認する

何のために
Claude が、利用者の Suno アカウントを使えるようにするため。この接続に API キーは要らない。 Suno にサインインして、アクセスを一度承認する方式である。 [1]

操作
追加した「 Suno 」の「 Connect 」を選ぶ。 [2] ブラウザなどで Suno のサインインの画面が表示されたら、自分の Suno アカウントでサインインし、求められた権限を読んでから承認する。権限の内容は確かめずに承認しない(第 9 章を参照)。

うまくいったとき
サインインと承認が終わり、 Suno が接続済みの状態になると想定される(作成者の解釈。未確認)。具体的な表示の文言は、資料で確認できなかった。

うまくいかないとき
サインインの画面を途中で閉じたときは、もう一度「 Connect 」を選んでみる(作成者の推奨。公式資料の記述ではない)。それでも進まないときは、 Suno の公式ガイドを確認する。 [2]

5.2 経路 A-2 : Claude アプリの Code タブ

この節は、経路 A-2 を選んだ人向けである。 Code タブは、 Claude のデスクトップアプリの中で Claude Code を使う画面である。 [9] コネクタを追加する操作は、 Anthropic の資料によれば、 Claude のアカウントでの、ローカルまたは SSH(別のコンピュータへの接続)のセッションが対象である。 [9]

ステップ A2-1 : Code タブでコネクタの画面を開く

何のために
Code タブから、コネクタを追加する入口に移るため。

操作
Code タブで、プロンプトの入力欄の横の「 + 」を選び、「 Add connectors 」を選ぶと、コネクタの一覧が開く。メニューに「 Connectors 」と表示されている場合は、それを選び、「 Browse connectors 」を選ぶ。 [9]

うまくいったとき
コネクタの一覧が開くと想定される(作成者の解釈。未確認)。

うまくいかないとき
WSL(Windows 上の Linux 環境)のセッションでは、「 Connectors 」の項目がグレーになる。 [9] その場合は、 WSL でないセッションで開き直してみる(作成者の推奨。資料に対処の記載はない)。 Code タブが開けないときや、必要なプランは、資料で確認できなかった。 Anthropic の公式ドキュメントを確認してほしい。 [9]

ステップ A2-2 : Suno を追加する

何のために
一覧に目的のコネクタがないときの代わりの方法を使うため。 Suno が Code タブの一覧に載っているかは、資料で確認できなかった。

操作
一覧に Suno が見当たらないときは、カスタムコネクタとして追加する。 Anthropic の資料は、一覧にない連携は、設定ファイルへの手動の追加か、カスタムコネクタの作成で行うと説明している。 [9] ただし、 Code タブでの追加が経路 A-1 のステップ A1-2 と A1-3 と同じ手順になるか、また Claude アプリで追加したコネクタが Code タブにも現れるかは、資料で確認できなかった(要確認)。確実に進めたいときは、経路 A-1 で追加する。コネクタの管理や接続の解除は、サイドバーの「 Customize 」から「 Connectors 」を開いて行う。 [9]

うまくいったとき
コネクタの管理画面に Suno が現れると想定される(作成者の解釈。未確認)。

うまくいかないとき
経路 A-1 に切り替える。または、 Anthropic の公式ドキュメントを確認する。 [9]

5.3 経路 B : ターミナルの Claude Code

この節は、経路 B を選んだ人向けである。コマンドを打つ場所が二か所あることに注意してほしい。 claude で始まる claude --version や claude mcp add などは、ターミナルの画面で打つ。 /login や /mcp のように / で始まるものは、 claude を起動したあとの、 Claude Code の入力欄に打つ。 claude コマンドの CLI(コマンドで操作する形)は、 Claude Code のターミナル版である。

ステップ B1 : ターミナルを開く

何のために
コマンドを打ち込む窓を用意するため。

操作
Windows では PowerShell 7 を、 Mac ではターミナル(zsh)を開く。

うまくいったとき
入力待ちの画面が開く。 Windows で PowerShell を使っているときは、 Anthropic の資料によれば、行の先頭に PS C:\ が表示される。 [8] Mac の zsh での表示は、資料で確認できなかった。

うまくいかないとき
開き方が分からないときは、 OS の案内や、 Anthropic のドキュメントを確認する。ターミナルや PowerShell 7 の入手・起動の詳しい手順は、本書の範囲外である。

ステップ B2 : Claude Code をインストールする

何のために
ターミナルで claude コマンドを使えるようにするため。すでに Claude Code を入れている人は、このステップを飛ばしてよい。

操作
OS に合うほうを打つ。 Windows の PowerShell には次を打つ。 [8]

irm https://claude.ai/install.ps1 | iex

Mac の zsh には次を打つ。 [8]

curl -fsSL https://claude.ai/install.sh | bash

どちらも、インターネット上のインストール用の命令を取り込んで、そのまま実行するコマンドである。 Anthropic の公式ページに書かれたこの形のままを使い、ほかのページで見つけた別の URL は使わない。 Windows のコマンドプロンプト(CMD)用のコマンドは別のものである。 PowerShell と取り違えないよう、画面の行頭に PS が付いていることを確かめる。 [8]

うまくいったとき
エラーなく終わる。成功したかどうかは、次のステップで確かめる。

うまくいかないとき
エラーが出たら、コマンドを打った場所(PowerShell か CMD か)と、自分の OS に合うコマンドかを見直す(作成者の推奨)。 OS ごとのコマンドの違いは資料にある。 [8] そのほかの失敗は、 Anthropic のインストールの案内(Troubleshoot installation)を確認する。 [8]

ステップ B3 : インストールを確かめる

何のために
インストールが成功し、 claude が呼び出せることを確かめるため。

操作
ターミナルを開き直して(新しいウィンドウにして)、次を打つ。 Windows でも Mac でも同じである。 [8]

claude --version

うまくいったとき
バージョン番号が表示される。 [8](作成者の手元の確認では、バージョン番号に続けて (Claude Code) と表示された。)

うまくいかないとき
シェルが claude を見つけられないと言ったら、インストール先が PATH(コマンドを探す場所の一覧)に入っていない。 Anthropic の Quickstart の PATH に関する案内を確認する。 [8]

ステップ B4 : Claude Code にログインする

何のために
Claude Code が、利用者の Claude のアカウントで動くようにするため。

操作
使いたい作業フォルダを一つ決め、そこに移動してから、 claude を起動する。 [8] ステップ B5 で追加する接続は、既定では、追加したフォルダ(プロジェクト)の中でだけ有効になる。 [6] 以後は、ステップ B5 も B6 も、このフォルダで行う。全部のフォルダで使う設定もあるが、その書式は Anthropic の資料で確認してほしい。 [6]

cd <あなたの作業フォルダのパス>
claude

<あなたの作業フォルダのパス> には、自分で使うフォルダの場所を入れる。 Anthropic の資料は、 cd のあとにプロジェクトのパスを入れて claude を起動する形を示している。 [8] 初回は、ログインを求められる。画面の案内に従い、ブラウザで認証する。 [8]

うまくいったとき
バージョン、現在のモデル、作業フォルダが上に表示された Claude Code の入力欄が現れる。 [8] ログインが終わったら、入力欄で /exit を打って、いったん Claude Code を終了する。 [8]

うまくいかないとき
ログインし直すときは、入力欄で /login を打つ。 [8]

ステップ B5 : Suno を追加する

何のために
Suno の接続口を、 Claude Code に登録するため。

操作
ステップ B4 と同じフォルダで、ターミナルの画面に次を打つ。 Windows でも Mac でも同じ形である。 [1][2]

claude mcp add --transport http suno https://api.suno.com/mcp

このコマンドは、「 HTTP という方式で、 suno という名前の接続口を、この URL で登録する」という意味である。 [6] オプション(--transport など)は、名前と URL より前に置く。 [6]

うまくいったとき
エラーが出ずに終わると想定される(作成者の解釈。未確認)。接続の状態は、ステップ B6 と第 6 章で確かめる。

うまくいかないとき
コマンドを打ち間違えていないか、特に URL を確かめる。 claude mcp add --help を打つと、書式の説明が表示される(作成者の手元で確認した)。

ステップ B6 : Suno にサインインして承認する

何のために
Claude Code が、利用者の Suno アカウントを使えるようにするため。 API キーは要らない。 [1]

操作
ステップ B4 と同じフォルダで claude を起動し、入力欄に次を打つ。 [6]

/mcp

ブラウザでの手順に従い、 Suno にサインインして承認する。 [6] 求められた権限は、読んでから承認する。 [7]

うまくいったとき
サインインと承認が終わると想定される(作成者の解釈。未確認)。具体的な表示の文言は、資料で確認できなかった。

うまくいかないとき
ブラウザが自動で開かないときは、画面に表示された URL をコピーして、手でブラウザに貼り付けて開く。 [6]

6. 接続の確認

追加しただけでは、つながったとは限らない。曲をつくる前に、次の方法で確かめる。

6.1 経路 A の確認

何のために
追加したコネクタが、会話で使える状態かを確かめるため。

操作
「 Customize > Connectors 」の一覧に「 Suno 」があることを確かめる。さらに、会話の画面で「 + 」を選び、「 Connectors 」を選んで、 Suno のスイッチがオンになっていることを確かめる。 [7]

うまくいったとき
一覧に Suno があり、会話でオンになっていると想定される(作成者の解釈。未確認)。

経路 A-2 (Code タブ)で追加したときは、サイドバーの「 Customize 」から「 Connectors 」を開いて、 Suno があるかを確かめる。 [9] 会話でのオンの操作が Code タブでも同じ表示かは、資料で確認できなかった(要確認)。

うまくいかないとき
Suno が一覧にないときは、ステップ A1-2 をやり直す。オフのときは、オンにする。 Suno の FAQ は、 Suno が AI アシスタントの接続一覧に自動では出ないことがあり、そのときはカスタムコネクタとして追加するよう案内している。 [3]

6.2 経路 B の確認

何のために
登録した接続口が、 Claude Code から見えているかを確かめるため。

操作
ターミナルで、次を打つ。登録済みの接続口の一覧が表示される。 [6]

claude mcp list

また、 Claude Code の入力欄で /mcp を打つと、接続の状態を確かめられる。 [6]

うまくいったとき
一覧に suno が出ると想定される(作成者の解釈。未確認)。状態を示す表示の文言は、資料で確認できなかった。

うまくいかないとき
一覧に出ないときは、追加したときと別のフォルダで確かめていないか見直す。既定の追加先は、そのフォルダの中だけで有効だからである。 [6]

6.3 共通の確認 : 残りのクレジットを尋ねる

何のために
実際に Claude から Suno を呼び出せることを、曲をつくる前に確かめるため。

操作
Claude の会話に、たとえば次のように頼む。 Suno の公式ページは、 AI ツールに残りのクレジットを尋ねられると説明している。 [1]

Suno の残りのクレジットを教えてください。

これは例であり、言い回しは自由に変えてよい。残量の問い合わせでクレジットが減るかは、資料に記載がなく、確認できなかった。

うまくいったとき
Claude が Suno に問い合わせて、残りのクレジットを答えると想定される(作成者の解釈。未確認)。途中で、道具の使用を許可するか尋ねる画面が出ることがある(第 7 章の 7.2 を参照)。

うまくいかないとき
Claude が Suno を使えないと答えるときは、接続が済んでいないか、会話で Suno がオフになっている可能性がある。ステップ A1-3 または B6 のサインインと承認が終わっているか、 Suno が会話でオンになっているかを見直す。 [3][7]

7. 曲をつくる

費用の注意。曲をつくるとクレジットを消費する。 Suno の公式ページは、曲のクレジットは現在のプランのものを使い、 suno.com でつくるときと同じだと説明している。 [1] 頼む曲の数は、依頼文に書いておくことをおすすめする(作成者の推奨)。

7.1 最初の一曲

何のために
接続できた状態で、実際に一曲つくり、流れを確かめるため。

操作
Claude の会話で、つくりたい曲を言葉で説明する。数は「一曲だけ」と明示する。次は依頼文の例である。ジャンルや内容は自由に変えてよい。

Suno で、雨の日の散歩をテーマにした、やさしいアコースティックギターの曲を一曲だけつくってください。歌詞とスタイルは任せます。
Suno で、朝のコーヒーをテーマにした、明るい短い曲を一曲だけつくってください。つくる前に、歌詞の案を見せてください。

二つ目の例のように「つくる前に案を見せてください」と添えると、クレジットを使う前に内容を確かめられる可能性がある。これは作成者の工夫であり、公式資料の記述ではない。日本語の歌詞に対応しているかは、資料で確認できなかった。思いどおりにならないときは、依頼文を変えて試す。

うまくいったとき
Claude が Suno に依頼し、結果を知らせると想定される(作成者の解釈。未確認)。つくった曲は、 Suno のライブラリに自動で保存される。 [3] 「一曲だけ」と頼んだときに、 Suno が実際に何曲つくり、クレジットをいくつ消費するかは、資料で確認できなかった(要確認)。

うまくいかないとき
途中で止まるときは、許可を求める画面が出ていないかを見る。エラーが出るときは、第 8 章の対処を確かめる。

7.2 許可を求められたとき

何のために
Claude が道具(ここでは Suno)を使う前に、利用者が内容を確かめるため。

操作
Claude アプリでは、道具の使用の承認を求められることがある。内容を読んでから許可する。「 Allow always 」は、信頼できるサーバーとツールにだけ使う。 [7] Code タブの Manual モードでは、ファイルの編集やコマンドの実行の前に、 Claude が確認を求める。 [9] ターミナルの Claude Code のモードの名前が同じかは、資料で確認できなかった(要確認)。

うまくいったとき
依頼の内容(曲の数など)と一致する操作だけを許可できると想定される(作成者の解釈。未確認)。

うまくいかないとき
身に覚えのない操作を求められたら、許可せずに止める。詳しくは第 9 章を読む。

7.3 できた曲を確かめる

何のために
曲が実際に保存されたことを、 Suno 側で確かめるため。

操作
suno.com にサインインし、ライブラリを開く。 [3]

うまくいったとき
依頼した曲がライブラリに並ぶと想定される(作成者の解釈。未確認)。 [3]

うまくいかないとき
曲がないときは、 Claude の会話の返答を読み直す。エラーがなかったかを見る。

7.4 そのほかにできること

Suno の公式ページによれば、音声から曲をつくる、カバー・マッシュアップ・延長をつくる、保存した Suno Voices を使う、といった使い方もある。 [1] ただし、本書は手順を確かめていない。個人の音声をアップロードするときは、その扱いを Suno の規約で確かめてからにする。

9. 安全・費用・規約

9.1 接続先を信頼してよいか

  • カスタムコネクタは、 Anthropic が検証していない任意のサービスにも、 Claude をつなげてしまう。 [7]
  • Anthropic は、 MCP サーバーのセキュリティ監査も管理も行っていない。信頼できる提供元のサーバーを使うよう、 Anthropic は勧めている。 [10]
  • 接続先の URL は、本書に書いた https://api.suno.com/mcp を、 Suno の公式ページ・ヘルプで照合してから使う。 [1][2] 似た名前の別のサーバーや、個人が作った非公式の接続口は、本書では扱わない。サインインの権限を預ける相手として、安全が確認できないためである。
  • 「公式」とは、 Suno 自身が提供しているという意味である。安全の保証ではない。 API キーが要らないことも、安全を意味しない。サインインして承認すること自体が、アクセス権を渡す行為だからである。

9.2 Claude に操作やコマンドを任せるとき

プロンプトインジェクションとは、攻撃者が悪意ある文章を紛れ込ませて、 AI の指示を上書きしようとする手口である(この定義は、 Anthropic の資料の説明に基づく作成者の訳である)。 [10] Anthropic の資料は、外部の内容を取りに行くサーバーが、この危険にさらされうると述べている。 [6] また、悪意のある MCP サーバーには、 Claude に意図しない行動をさせる隠れた指示が含まれうる。 [7]

  • 提案されたコマンドは、内容を読んでから許可する。承認の前に、提案されたコードやコマンドの安全を確かめるのは、利用者の責任だとされている。 [10]
  • 「 Allow always 」は、信頼できるサーバーとツールにだけ使う。関係のないツールは、無効にしておく。 [7]
  • 権限モードは、確認を求める Manual を使うことをおすすめする。 Bypass permissions(名前から、確認を省く設定と解釈される。作成者の解釈)は、使わないほうがよい(作成者の推奨)。 [9]
  • 元の投稿の方法を試すとき。 Claude が読もうとしている URL が、 Suno 自身の公式ページか確かめる。実行しようとするコマンドが、本書のステップ B5 のコマンド(claude mcp add --transport http suno https://api.suno.com/mcp)と一致するか確かめる。一致しない、または意味の分からないコマンドは許可しない(作成者の推奨)。

9.3 費用

曲をつくるとクレジットを消費する。 [1][3] クレジットの量・必要数・料金は変わりうるため、 Suno の公式ページで最新の内容を確かめる。取得日は 2026-10-31 である。 Claude 側の料金やプランも、 Anthropic の公式ページで確かめる。

9.4 つくった曲の権利

Suno のヘルプ(取得日 2026-10-31 、更新日の記載なし)によれば、曲をつくった時点で Pro か Premier のプランに加入していれば、その曲の所有者とみなされ、加入をやめても商用利用の権利が残る。無料(Free)のプランでつくった曲は Suno が所有権を保持し、非商用でのみ使える。 [4] プランの名前や条件は変わりうる。公開や販売をする前に、必ず最新のヘルプと規約を確かめてほしい。

9.5 接続をやめる・取り消す

  • 経路 A : 「 Customize > Connectors 」で、コネクタの「 Remove 」を選ぶ。 [7] これで Suno 側の許可も失効するかは、資料で確認できなかった(要確認)。
  • 経路 B : 次の順に行う。 [6]
    1. ステップ B4 と同じフォルダで(作成者の推奨。追加した場所が local スコープのため)、ターミナルで claude mcp logout <name> を実行する。保存された認証情報を消し、許可の失効を試みる手順である。
    2. 続けて claude mcp remove <name> を実行し、登録を削除する。
    <name> は、登録した名前(本書では suno)である。順序を逆にすると、削除だけでは、ローカルのトークンは消えても、発行元での失効はされない。 [6] Claude Code の中で /mcp を開き、「 Clear authentication 」を選んでもアクセスを取り消せる。 [6]
  • Suno 側のアカウントの設定で、許可を取り消す方法は、資料で確認できなかった。

9.6 認証情報の扱い

認証情報(パスワード・キー・トークン)を、チャットの会話、文書、共有ファイルに貼り付けない。 Suno へのサインインは、ブラウザの Suno の画面で行う。 Claude の会話欄にパスワードを書く必要はない。

Anthropic の資料によれば、 Claude Code の API キーやトークン(サインインの証明となる文字列)は、 Mac では、使える場合は Keychain(Mac の認証情報の保管庫)に、 Windows では、利用者のプロファイルのフォルダの権限を引き継ぐファイルに保存される。 [10] 共用のパソコンでは、サインインしたままにしないことをおすすめする(作成者の推奨)。

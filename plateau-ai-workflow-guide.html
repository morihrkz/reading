1この手引書の位置づけ

1.1 完成物と所要時間

完成物は、東京・渋谷のように実在する街の構造を保った、 8 〜 16 秒ほどの FPV ドローン風の映像です。 FPV とは、機体のカメラ視点で飛ぶ、低空・高速・急旋回を特徴とする撮影様式を指します。

所要時間の目安は次のとおりです。初回は、準備とつまずきの解消に時間を取られます。 2 回目以降は、同じ街なら工程 3 から繰り返せます。

工程内容初回の目安2 回目以降
準備ソフトの導入、フォルダ作成1 〜 2 時間なし
工程 1PLATEAU データの入手30 分なし
工程 2Blender で街を組む1 時間なし
工程 3カメラ経路の設計1 〜 2 時間30 分

1.2 できないこと・注意点

動画生成 AI は、入力した 3D の形をそのまま保存する装置ではありません。建物の位置と高さを「参考にする」だけなので、看板の文字、窓の数、細部の形は AI が作り直します。測量や設計の資料としては使えません。

  • スクリプトの修正などを任せる AI エージェントには、 Claude Code のような、手元の PC でコードを実行できるものを想定します。
  • コマンドとパスは、 Mac （ zsh ）を前提に書いています。 Windows では、 Blender の実行ファイルのパスを C:\Program Files\Blender Foundation\Blender 4.2\blender.exe のように読み替え、 PowerShell で実行してください。
  • 各サービスの料金、商用利用の可否、生成できる長さは、利用時点の公式ページで確認してください。
  • Blender のスクリプトは、 Blender 4.2 LTS または 4.5 LTS の API を前提にしています。 5.0 以降は、コンポジター関連の API が変わっている可能性があります。
  • PLATEAU の配布物の構成（フォルダ名、ファイル名）は年度やデータセットで異なります。手引書の記述と違うときは、実物を見て読み替えてください。

2全体像

街の形と、カメラの動きと、見た目の質感を、別々の工程で決めます。 AI に任せるのは最後の「質感」だけで、街の形とカメラの動きは、人が数値で決めます。

  1. 工程 1
    PLATEAU の OBJ データを入手する。
  2. 工程 2
    Blender に取り込み、原点付近へ寄せ、空と太陽を置く。ここまでを build_scene.py で自動化する。
  3. 工程 3
    飛行経路を、座標と秒数の表（ path.json ）にする。
  4. 工程 4
    render_path.py が、経路どおりに飛ぶ連番画像と、深度の連番画像を書き出す。
  5. 工程 5
    動画生成 AI に渡し、実写風にする。
  6. 工程 6
    クリップを連結し、色を整え、書き出す。

4工程 1 PLATEAU データを入手する

4.1 対象エリアを決める

PLATEAU のデータは、地域メッシュ（約 1km 四方の区画）ごとに分かれています。メッシュは 8 桁の番号で表されます。必要な区画だけを取れば、読み込みが軽く、失敗も減ります。

渋谷駅からスクランブル交差点にかけての範囲は、概算ではメッシュ番号 53393586 と 53393596 にまたがります。この番号は座標からの計算値なので、必ず地図で確かめてください。確かめ方は、次の 4.2 に書きます。

最初は、 1 区画（ 1km 四方）で始めてください。複数区画を組むと、データ量が数倍になり、 Blender が重くなります。飛行経路が区画をまたぐ場合に限って、隣の区画を足します。

4.2 ダウンロードと展開

  1. ブラウザで、国土交通省の PLATEAU の公式サイトを開き、データ配布の案内から、 G 空間情報センターの「 3D 都市モデル（ Project PLATEAU ）東京都 23 区」のページへ進む。
  2. データの一覧から、 OBJ 形式のものを探す。形式の一覧に OBJ が見当たらないときは、 CityGML しかない年度である。その場合は、同じ地域の別のデータセットを探すか、 PLATEAU 公式の変換ツールで OBJ に変換する。
  3. メッシュ番号が先頭に付いたファイルの中から、 4.1 で決めた番号のものだけを選ぶ。地域全体の zip ファイルは、数 GB になることがあるので避ける。
  4. ダウンロードしたファイルを、作業フォルダの plateau/ に展開する。
  5. 展開後、建物（ bldg ）、地形（ dem ）、道路（ tran ）などの種別ごとに、 .obj ファイルがあることを確認する。

建物のファイルが LOD1 （箱型）と LOD2 （屋根の形つき）の両方ある場合は、まず LOD2 を使います。テクスチャ（壁の写真）付きのデータは見栄えがよい反面、重いので、最初は付いていない方で通しで試す方が確実です。

4.3 利用条件と出典表示

  • PLATEAU のデータは、多くのデータセットで CC BY 4.0 の条件で提供されている。利用するデータセットのページで、実際のライセンス表記を必ず確認する。
  • 公開するときは、出典を表示する。書き方の例は「 3D 都市モデル（ Project PLATEAU ）を加工して作成」。表記の指定がデータセットのページにあれば、そちらに従う。
  • 出典の表示と、元データを加工した旨の明記は、動画の説明欄にも書く。

5工程 2 Blender で街を組み立てる

Blender の GUI で手作業をしても同じことができますが、手作業は再現しにくいので、スクリプトにします。スクリプトは自分で書く必要はありません。下のコードを保存して使い、エラーが出たら、エラー全文を AI に貼って直させます。

5.1 スクリプト build_scene.py

このスクリプトがやることは五つです。 OBJ の一括読み込み、向きの点検、街の中心を原点へ移動、空と太陽の設置、 .blend の保存です。 PLATEAU の座標は、原点から非常に遠い値になっていることがあり、そのままだと Blender の表示とレンダリングが乱れます。そのため、原点付近へ寄せます。

scripts/build_scene.py として保存します。

import bpy, sys, glob, os, math, argparse
from mathutils import Vector


def parse():
    argv = sys.argv[sys.argv.index("--") + 1:] if "--" in sys.argv else []
    p = argparse.ArgumentParser()
    p.add_argument("--obj-dir", required=True)
    p.add_argument("--out", required=True)
    p.add_argument("--up", default="Y")              # OBJ 側の上方向
    p.add_argument("--forward", default="NEGATIVE_Z")
    p.add_argument("--clay", action="store_true")    # 全面を灰色の粘土色にする
    p.add_argument("--sun-elevation", type=float, default=12.0)  # 太陽高度(度)
    p.add_argument("--sun-azimuth", type=float, default=-90.0)   # 太陽の向き(度)
    return p.parse_args(argv)


def bbox(objs):
    pts = [o.matrix_world @ Vector(c) for o in objs for c in o.bound_box]
    lo = Vector((min(p.x for p in pts), min(p.y for p in pts), min(p.z for p in pts)))
    hi = Vector((max(p.x for p in pts), max(p.y for p in pts), max(p.z for p in pts)))
    return lo, hi


a = parse()
bpy.ops.wm.read_factory_settings(use_empty=True)

files = sorted(glob.glob(os.path.join(a.obj_dir, "**", "*.obj"), recursive=True))
print("OBJ files:", len(files))
for f in files:
    print("import", f)
    bpy.ops.wm.obj_import(filepath=f, forward_axis=a.forward, up_axis=a.up)

bpy.context.view_layer.update()
objs = [o for o in bpy.context.scene.objects if o.type == "MESH"]
lo, hi = bbox(objs)
size = hi - lo
print("bbox min:", lo, "max:", hi, "size(m):", size)
if not (size.z < size.x and size.z < size.y):
    print("WARNING: 高さ方向が最小の寸法になっていません。--up と --forward を変えて再実行してください。")

# 街の中心を原点へ、最も低い地点を高さ 0 へ
shift = Vector(((lo.x + hi.x) / 2, (lo.y + hi.y) / 2, lo.z))
for o in objs:
    o.location -= shift
bpy.context.view_layer.update()

# 材質: 粘土色
if a.clay:
    mat = bpy.data.materials.new("clay")
    mat.use_nodes = True
    mat.node_tree.nodes["Principled BSDF"].inputs["Base Color"].default_value = (0.75, 0.75, 0.72, 1)
    for o in objs:
        o.data.materials.clear()
        o.data.materials.append(mat)

# 空(太陽の円盤は無効。影は Sun ライトで作る)
world = bpy.data.worlds.new("world")
bpy.context.scene.world = world
world.use_nodes = True
nt = world.node_tree
sky = nt.nodes.new("ShaderNodeTexSky")
sky.sky_type = "NISHITA"
sky.sun_disc = False
sky.sun_elevation = math.radians(a.sun_elevation)
sky.sun_rotation = math.radians(a.sun_azimuth)
nt.links.new(sky.outputs["Color"], nt.nodes["Background"].inputs["Color"])

# 太陽: ライトは自分の -Z 方向へ光を出す
sun_data = bpy.data.lights.new("sun", "SUN")
sun_data.energy = 4.0
sun_data.color = (1.0, 0.82, 0.62)
sun = bpy.data.objects.new("sun", sun_data)
bpy.context.scene.collection.objects.link(sun)
sun.rotation_euler = (math.radians(90 - a.sun_elevation), 0, math.radians(a.sun_azimuth))

bpy.ops.wm.save_as_mainfile(filepath=a.out)
print("saved:", a.out)

5.2 実行方法

Blender を GUI を使わずに起動し（ -b ）、スクリプトを渡します（ -P ）。スクリプトへの引数は、 -- の後ろに書きます。ターミナル（ zsh ）で、フォルダ shibuya-fpv に移動してから実行します。

/Applications/Blender.app/Contents/MacOS/Blender -b -P scripts/build_scene.py -- --obj-dir plateau --out work/city.blend --clay

最初は --clay を付けてください。粘土色にすると、形が正しいかどうかを確かめやすくなります。実行後、出力に出る「 bbox 」と「 size 」の行を確認します。 size の三つの値のうち、 Z （高さ）が最小であれば、向きは正しい読み込みです。警告が出たときは、 --up Z --forward Y のように変えて、再実行してください。

6工程 3 カメラ経路を設計する

ここが、この手法の中心です。経路を数値で確定しておけば、動画生成 AI のやり直しを何回しても、同じ飛行を基準にできます。

6.1 設計の数値目安

項目目安理由
全体の長さ5 〜 8 秒を一区間にする動画生成 AI が破綻せずに生成できる長さに合わせる。長い映像は区間を連結する
フレームレート24fps映画的な動きになり、動画生成 AI の標準とも合う
飛行速度15 〜 30m/ 秒これ以下だと、普通のドローンの映像に見える。これ以上だと、動画生成 AI が追従できない
高度低空は地上 3 〜 6m 、上昇時は 70m まで低いほど速く見えるが、建物に近すぎると形が崩れる。壁面から最低 5m は離す
焦点距離12 〜 16mm （センサー幅 36mm ）14mm で水平画角は約 104 度。 10mm 未満は端の歪みが強く、動画生成 AI が混乱する
急旋回1 秒あたり 90 度以内、ロール（傾き）は ±15 度動きが急すぎると、動画生成 AI が前後のフレームの対応を見失う
視線の先常に、進行方向の少し先を見る進行方向と視線がずれると、横滑りのような不自然な動きになる

6.2 座標の測り方

経路は、 Blender 上の座標（単位はメートル）で書きます。測り方は次のとおりです。

  1. Blender で work/city.blend を開き、テンキーの 7 で真上から見て、 テンキーの 5 で、平行投影に切り替える（テンキーがないときは、ビューポート上部の「ビュー」メニューから選ぶ）。
  2. 通りたい道の上で、 Shift キーを押しながら右クリックして、 3D カーソルを置く。
  3. マウスを 3D ビューポートの上に置いて N キーを押し、サイドバーを開く。次に、「ビュー」タブの「 3D カーソル」の位置から、 X と Y の値を読む。
  4. 高さ Z は、地面の高さに、希望する地上高を足して決める。地面の高さは、横から見て調べるか、まず 0 として試し撮りで確かめる。
  5. 通過点を五つ程度（スタート、中間三つ、終点）書き留める。進行方向の少し先を、それぞれ「見る点」として書く。

経路が建物の中を通ると、画面が真っ暗になったり、壁の内側が映ったりします。試し撮りで必ず確認します。通過点は、道路の中央に取ると安全です。

6.3 経路ファイル path.json

通過点を、時刻（秒）と合わせて scripts/path.json に書きます。次の数値は書き方の例です。座標は、自分の測った値に置き換えます。

{
  "lens": 14,
  "fps": 24,
  "shake": 0.5,
  "depth_range": 300,
  "waypoints": [
    {"t": 0.0, "pos": [-60, -30, 6],  "look": [0, 0, 6],    "roll": 0},
    {"t": 2.0, "pos": [-30, -12, 3],  "look": [10, 10, 5],  "roll": -8},
    {"t": 4.0, "pos": [5, 5, 3],      "look": [40, 40, 10], "roll": 6},
    {"t": 6.0, "pos": [35, 30, 12],   "look": [60, 60, 30], "roll": -10},
    {"t": 8.0, "pos": [45, 45, 70],   "look": [50, 50, 120], "roll": 0}
  ]
}
キー意味
lens焦点距離（ mm ）
fpsフレームレート
shakeカメラの揺れの強さ。 0 で揺れなし、 1 で位置が約 5cm 、傾きが約 1.5 度揺れる。 AI に変換させる場合は 0.3 〜 0.5 にとどめる
depth_range深度画像の白から黒までの距離（ m ）。街の幅が約 1km なら 300 前後
tその通過点を通る時刻（秒）
posカメラの位置 [X, Y, Z] （ m ）
lookその時刻に見ている点 [X, Y, Z] （ m ）
roll傾き（度）。旋回方向に倒すと、ドローンらしく見える

例の経路の速度は、区間の距離を秒数で割ると約 17 〜 30m/ 秒になります。自分の経路でも、区間ごとに距離を測り、 6.1 の目安に収まるかを確かめてください。この計算は、 AI に任せても構いません。

7工程 4 レンダリングする

7.1 スクリプト render_path.py

このスクリプトは、 path.json の通過点をなめらかな曲線でつないで、 1 フレームごとのカメラ位置と向きを計算し、色と深度の連番画像を書き出します。深度は、近いほど白く（ミスト パスの出力）なります。もし逆に出た場合は、 ffmpeg で反転します。

scripts/render_path.py として保存します。

import bpy, sys, os, json, math, random, argparse
from mathutils import Vector, Quaternion


def parse():
    argv = sys.argv[sys.argv.index("--") + 1:] if "--" in sys.argv else []
    p = argparse.ArgumentParser()
    p.add_argument("--path", required=True)
    p.add_argument("--out-dir", required=True)
    p.add_argument("--width", type=int, default=1280)
    p.add_argument("--height", type=int, default=720)
    p.add_argument("--samples", type=int, default=32)
    p.add_argument("--frame-start", type=int, default=None)
    p.add_argument("--frame-end", type=int, default=None)
    p.add_argument("--no-depth", action="store_true")
    return p.parse_args(argv)


def hermite(pts, ts, t):
    """通過点を滑らかにつなぐ曲線(Catmull-Rom 型のエルミート補間)"""
    n = len(ts)
    if t <= ts[0]:
        return pts[0].copy()
    if t >= ts[-1]:
        return pts[-1].copy()
    i = max(k for k in range(n - 1) if ts[k] <= t)
    h = ts[i + 1] - ts[i]
    s = (t - ts[i]) / h

    def tangent(k):
        lo, hi = max(k - 1, 0), min(k + 1, n - 1)
        return (pts[hi] - pts[lo]) / (ts[hi] - ts[lo])

    m0, m1 = tangent(i) * h, tangent(i + 1) * h
    s2, s3 = s * s, s * s * s
    return ((2 * s3 - 3 * s2 + 1) * pts[i] + (s3 - 2 * s2 + s) * m0
            + (-2 * s3 + 3 * s2) * pts[i + 1] + (s3 - s2) * m1)


a = parse()
cfg = json.load(open(a.path, encoding="utf-8"))
wps = cfg["waypoints"]
ts = [w["t"] for w in wps]
P = [Vector(w["pos"]) for w in wps]
L = [Vector(w["look"]) for w in wps]
R = [Vector((w.get("roll", 0), 0, 0)) for w in wps]
fps = cfg.get("fps", 24)
shake = cfg.get("shake", 0.0)

scn = bpy.context.scene
scn.render.fps = fps
scn.render.resolution_x = a.width
scn.render.resolution_y = a.height
scn.render.resolution_percentage = 100
try:
    scn.render.engine = "BLENDER_EEVEE_NEXT"
except TypeError:
    scn.render.engine = "BLENDER_EEVEE"
scn.eevee.taa_render_samples = a.samples

# カメラ
cam_data = bpy.data.cameras.new("fpv")
cam_data.lens = cfg.get("lens", 14)
cam_data.sensor_width = 36
cam_data.clip_start = 0.1
cam_data.clip_end = 5000
cam = bpy.data.objects.new("fpv", cam_data)
scn.collection.objects.link(cam)
scn.camera = cam
cam.rotation_mode = "QUATERNION"

rnd = random.Random(7)
ph = [rnd.uniform(0, 6.28) for _ in range(6)]


def noise(t):
    return Vector((
        math.sin(t * 5.1 + ph[0]) + 0.5 * math.sin(t * 11 + ph[1]),
        math.sin(t * 4.3 + ph[2]) + 0.5 * math.sin(t * 9 + ph[3]),
        math.sin(t * 6.7 + ph[4]) + 0.5 * math.sin(t * 13 + ph[5])))


total = int(round(ts[-1] * fps)) + 1
scn.frame_start, scn.frame_end = 1, total
for f in range(1, total + 1):
    t = (f - 1) / fps
    pos = hermite(P, ts, t)
    look = hermite(L, ts, t)
    roll = hermite(R, ts, t).x
    n = noise(t)
    pos += n * 0.05 * shake
    roll += n.x * 1.5 * shake
    q = (look - pos).to_track_quat("-Z", "Y")
    q = q @ Quaternion((0, 0, 1), math.radians(roll))
    cam.location = pos
    cam.rotation_quaternion = q
    cam.keyframe_insert("location", frame=f)
    cam.keyframe_insert("rotation_quaternion", frame=f)

if a.frame_start is not None:
    scn.frame_start = a.frame_start
if a.frame_end is not None:
    scn.frame_end = a.frame_end

# 出力先
rgb_dir = os.path.join(a.out_dir, "rgb")
os.makedirs(rgb_dir, exist_ok=True)
scn.render.filepath = os.path.join(rgb_dir, "frame_")
scn.render.image_settings.file_format = "PNG"

# 深度(ミスト パス)を別の連番として出す
if not a.no_depth:
    depth_dir = os.path.join(a.out_dir, "depth")
    os.makedirs(depth_dir, exist_ok=True)
    scn.world.mist_settings.start = 0
    scn.world.mist_settings.depth = cfg.get("depth_range", 300)
    bpy.context.view_layer.use_pass_mist = True
    scn.use_nodes = True
    nt = scn.node_tree
    nt.nodes.clear()
    rl = nt.nodes.new("CompositorNodeRLayers")
    comp = nt.nodes.new("CompositorNodeComposite")
    fo = nt.nodes.new("CompositorNodeOutputFile")
    fo.base_path = depth_dir
    fo.format.file_format = "PNG"
    fo.format.color_mode = "BW"
    fo.format.color_depth = "16"
    fo.file_slots[0].path = "depth_"
    nt.links.new(rl.outputs["Image"], comp.inputs["Image"])
    nt.links.new(rl.outputs["Mist"], fo.inputs[0])

bpy.ops.render.render(animation=True)
print("done:", a.out_dir)

7.3 連番画像を動画にする

動画生成 AI は、連番画像ではなく動画ファイルを受け取ります。 FFmpeg で、色と深度をそれぞれ動画にします。深度が逆（遠いほど白）の場合は、 -vf negate を付けて反転します。

ffmpeg -framerate 24 -i work/render/rgb/frame_%04d.png -c:v libx264 -pix_fmt yuv420p -crf 18 work/render/previz.mp4
ffmpeg -framerate 24 -i work/render/depth/depth_%04d.png -c:v libx264 -pix_fmt yuv420p -crf 18 work/render/depth.mp4

8工程 5 動画生成 AI で実写風にする

二つの方式があります。まず方式 A で全体を通し、街の崩れが目立つときに方式 B を試します。

8.1 方式 A 画像から動画

最も手軽な方式です。経路は、プロンプトの文章でしか伝わらないため、経路どおりには飛びません。

  1. 工程 4 の frame_0001.png を、動画生成 AI の「画像から動画（ Image to Video ）」に入力する。
  2. 終点の画像（最終フレーム）を入れられるサービスなら、 frame_0193.png のような最終フレームも入力する。始点と終点を固定すると、建物の位置がずれにくくなる。
  3. 長さを 5 秒（選べないときは最短）にし、 8.3 のプロンプトを入力する。
  4. 4 〜 8 本を生成し、 8.4 の基準で選ぶ。

8.2 方式 B 動画から動画

工程 4 で作った動画（ previz.mp4 ）を元に、動画生成 AI が質感だけを作り替える方式です。経路が動画の中に含まれているので、飛行は経路どおりになり、建物の位置もずれにくくなります。

  1. 動画生成 AI の「動画から動画（ video-to-video 、リスタイル、構造維持などの名前）」の機能を探す。
  2. previz.mp4 を入力し、 8.3 のプロンプトを入力する。変化の強さを調節する項目があれば、中程度（半分前後）から始める。強すぎると街が作り替えられ、弱すぎると CG のままになる。
  3. 深度動画を入力できる機能（深度による制御）があれば、 depth.mp4 も入力する。
  4. 4 〜 8 本を生成し、 8.4 の基準で選ぶ。

手元に高性能な GPU がある場合は、 ComfyUI などで、深度による制御つきの動画生成モデルを動かす方法もあります。設定の自由度は高いものの、環境づくりに手間がかかるので、まず商用サービスで試してください。

8.3 プロンプトの組み立て

プロンプトは、英語の方が効くサービスが多く、本手引書も英語を勧めます。次の五つの要素を、この順に並べます。

要素書くこと例
1. 場所と被写体実在の街であること、画面にあるものTokyo Shibuya crossing, skyscrapers, wide asphalt streets
2. 光と時間帯夕方、空の色、反射golden hour, warm low sun, sun reflecting on glass facades
3. カメラFPV ドローンであること、動きFPV drone shot, fast forward flight low above the street, then climbing along a tower
4. 質感実写らしさphotorealistic, cinematic, detailed asphalt texture, slight motion blur
5. 守ってほしいこと構造を変えない、余計なものを足さないkeep the exact building layout and heights, no new buildings, no text overlays

つなげると、次のようになります。

Tokyo Shibuya crossing at golden hour, warm low sun reflecting on glass facades.
FPV drone shot, fast forward flight low above the street between skyscrapers,
then a steep climb along one tower. Photorealistic, cinematic, detailed asphalt
texture, slight motion blur. Keep the exact building layout and heights.
No new buildings, no text overlays.

ネガティブプロンプトの欄があるサービスでは、 warping buildings, melting walls, floating objects, extra buildings, text, watermark, cartoon のように、起こしてほしくないことを列挙します。

動きの指示を、長く書きすぎないでください。経路は、方式 B なら動画に含まれ、方式 A でも画像で位置が固定されています。プロンプトは「質感」の指示に使い、動きは短い言葉にとどめる方が、結果が安定します。

8.4 選別の基準

生成したクリップを、次の順で見て、落とします。上の項目ほど致命的で、直せません。

  1. 建物の形と高さが、元の 3D と合っているか
    最初と最後で、タワーの形が変わっていないか。変わっていれば不採用。
  2. 道路の向きと幅が合っているか
    交差点の位置が、経路の途中でずれていないか。
  3. カメラが、期待した動きをしているか
    上昇のタイミングが大きくずれていないか。
  4. ちらつき、変形がないか
    壁の窓が波打つ、車や人が溶ける、看板の文字が崩れる、などが目立たないか。小さい物の崩れは、速く飛ぶ映像なら目立ちにくい。
  5. 色と光が、夕方として自然か
    色は後で直せるので、最後に見る。

9工程 6 仕上げと書き出し

採用したクリップを、次の手順で一本にします。長い映像にしたいときは、工程 3 を次の区間用に作り直し、前のクリップの最終フレームを次の開始画像にして、工程 5 を繰り返します。

  1. 最終フレームの切り出し
    次のクリップの開始画像に使う。
  2. 連結
    クリップを並べる。コーデックと解像度が揃っていれば、再エンコードなしで連結できる。揃っていなければ、再エンコードする。
  3. 解像度と滑らかさ
    生成 AI の標準は 720p 〜 1080p が多い。必要に応じて、アップスケールや、フレーム補間（ 24fps から 30fps や 60fps へ）を使う。サービス内の機能か、専用のツールを使う。
  4. 色の調整
    クリップごとの色の差を揃える。夕方の色味を足すと、つなぎ目が目立たなくなる。
  5. 音
    風切り音や、街の環境音を重ねると、 FPV らしさが増す。音源の権利に注意する。

FFmpeg での操作例です。

ffmpeg -sseof -0.1 -i ai/clip01.mp4 -update 1 -q:v 1 ai/last01.png
ffmpeg -f concat -safe 0 -i ai/list.txt -c copy final/shibuya-fpv.mp4

list.txt には、連結する順にクリップを書きます。

file 'clip01.mp4'
file 'clip02.mp4'

11トラブルシューティング

症状考えられる原因対処
Blender で街が横倒し、または逆さ取り込み時の上方向の指定が違う--up と --forward を変えて再実行する
画面が真っ白、または真っ黒カメラが建物の中にある。または、街から遠すぎる経路の座標を確かめる。 3D 表示で、カメラの位置を見る
表示がガタガタ、建物が揺れる座標が原点から遠いbuild_scene.py の中心移動が効いているか確認する
描画が遅いデータが大きい。または、 GPU がない区画を減らす。解像度とサンプル数を下げる。テクスチャなし（ --clay ）にする
深度の白黒が逆ミスト パスの出力の向きFFmpeg に -vf negate を付けて反転する
AI の映像で、建物が別物になる変化が強すぎる。またはクリップが長すぎる方式 B に切り替える。変化の強さを下げる。 5 秒に短縮する
AI の映像が、 CG のまま変わらない変化が弱すぎる変化の強さを上げる。プロンプトの「質感」の要素を強める
つなぎ目で光や色が変わるクリップごとに別の絵として生成された前のクリップの最終フレームを、次の開始画像にする。仕上げで色を揃える
看板や窓が崩れる動画生成 AI の弱点高速で飛ぶ構図にして、見える時間を短くする。ネガティブプロンプトに text を入れる

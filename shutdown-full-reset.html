1この文書の背景

この文書は、作成者（ユーザー）が 2026-10-14 に Claude へ寄せた次の疑問への回答と、その結果としての設定手順をまとめたものである。

  • 疑問の前提 : 「 Windows でも Mac でも、『再起動』は『シャットダウン（システム終了）』よりも深いレベルまでプロセスを終了・リセットしているのではないか。シャットダウンは、終了時や次回起動時の時間を短縮するために、浅いレベルでしか行っていないのではないか。」
  • 目的 : 毎回シャットダウンするたびに、再起動と同じ深さまで終了・リセットされるようにしたい。
  • 対象 : Windows 11 （ Home 版）と macOS 26 。

以下の「認識」「見方」は、すべてこの疑問の前提を指す。

2結論

「再起動が深く、シャットダウンは浅い」という前提が、各 OS で成り立つかどうかを先にまとめる。

OS前提の当否必要な設定
Windows 11成り立つ。シャットダウンは既定で「高速スタートアップ」という半休止状態の保存を伴い、再起動より浅い。高速スタートアップを無効にする（第 4 章）。
macOS 26成り立たない。 Mac には Windows の高速スタートアップに相当する仕組みがなく、シャットダウンは再起動と同じく全プロセスと OS カーネルを終了する。プロセスのクリア度合いを上げる設定は不要（第 5 章）。

3前提の検証

3.1 Windows

疑問の前提のうち、「再起動の方が深い」は正しい。ただし「終了時の時間を短縮するため」という理由づけは少し違う。短縮されるのは主に次回の起動時間であり、終了処理はむしろ休止ファイル(hiberfil.sys)への書き出しが加わる分、わずかに長くなることがある。

操作ユーザーのアプリ・サインインOS カーネル・ドライバー
再起動すべて終了すべて終了し、次回に一から読み込み直す
シャットダウン（高速スタートアップ有効）すべて終了終了せず、状態を hiberfil.sys に保存して電源を切る。次回はそれを読み戻す
シャットダウン（高速スタートアップ無効）すべて終了すべて終了（再起動と同等）

つまり、カーネルとドライバーの状態が持ち越されることが「浅い」の正体である。長時間のうちに溜まったドライバーの不調やメモリの断片化が、シャットダウンでは解消されにくい。

3.2 Mac

Mac のシャットダウンでは、すべてのアプリとシステムプロセスが終了し、メモリの内容は破棄される。次の起動は一から始まる。休止状態の保存(hibernatemode)が関わるのはスリープ（蓋を閉じる操作を含む）であり、シャットダウンではない。

再起動との違いは、電源を一度落とすかどうかというハードウェア側の差にとどまる。プロセスの終了の深さに差はない。

4Windows 11 の設定

4.1 考え方

高速スタートアップをオフにすると、シャットダウンが従来どおりの完全な終了になる。手順は二通りある。いずれも結果は同じなので、やりやすい方を選ぶ。

Windows 11 Home にはグループポリシーエディター(gpedit.msc)がないため、ここでは使わない。

4.2 手順 A: 画面操作で設定する

  1. Win キーと R キーを同時に押し、 powercfg.cpl と入力して Enter を押す（電源オプションが開く）。
  2. 左側の「電源ボタンの動作を選択する」をクリックする。
  3. 「現在利用可能ではない設定を変更します」をクリックする（管理者の確認が出たら許可する）。
  4. 「シャットダウン設定」にある「高速スタートアップを有効にする（推奨）」のチェックを外す。
  5. 「変更の保存」をクリックする。
「高速スタートアップを有効にする」の項目自体が表示されない場合は、休止状態が無効になっている。すでに高速スタートアップは働いておらず、設定は不要である。

4.3 手順 B: コマンドで設定する

高速スタートアップのオン・オフは、レジストリの HiberbootEnabled の値で決まる。 0 にするとオフになる。スタートボタンを右クリックし、「ターミナル（管理者）」を開いて次を実行する。

reg add "HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Power" /v HiberbootEnabled /t REG_DWORD /d 0 /f

現在の値を確かめるには、次を実行する（ 0x0 ならオフ）。

reg query "HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Power" /v HiberbootEnabled
別の方法として powercfg /hibernate off でも高速スタートアップは無効になる。ただし休止状態の機能そのものが使えなくなり、休止ファイルも消える。休止状態を使うつもりがなければ有効な選択肢だが、手順 A か B の方が影響が小さい。

4.4 効果の確かめ方

  1. 設定を変更したあと、一度シャットダウンして電源を入れ直す。
  2. タスクマネージャー(Ctrl + Shift + Esc)を開き、「パフォーマンス」→「 CPU 」の「稼働時間」を見る。
  3. 電源を入れ直した直後の稼働時間が、ほぼ 0 から始まっていれば成功である。高速スタートアップが働いていると、シャットダウンをまたいで稼働時間が積み上がる。

4.5 その場かぎりで完全終了したいとき

設定を変えず、一回だけ完全なシャットダウンをする方法もある。

  • スタートメニューで Shift キーを押しながら「シャットダウン」をクリックする。
  • または、ターミナルで shutdown /s /full /t 0 を実行する。

4.6 付随する設定（任意）

シャットダウンのあと、サインイン時にアプリが自動で再び開く場合がある。「毎回まっさらにしたい」目的に合わせるなら、「設定」→「アカウント」→「サインイン オプション」にある「再起動可能なアプリを自動的に保存し、サインイン時に再起動する」（表記は版によって異なる）をオフにする。

4.7 元に戻す

手順 A ならチェックを入れ直す。手順 B なら、上のコマンドの /d 0 を /d 1 に変えて実行する。

デメリット : 高速スタートアップをオフにすると、電源を入れてからデスクトップが使えるまでの時間が長くなる。 SSD の機種では数秒から十数秒程度の差であることが多い。

大型の Windows 更新（機能更新）のあとに、この設定が既定の「有効」に戻ることがある。更新後は第 4.4 節の確認をやり直す。

5macOS 26 の設定

5.1 考え方

第 3.2 節のとおり、 Mac のシャットダウンは最初から完全な終了である。ここで「設定」として行うことは、確認と、任意の付随設定だけである。

5.2 確認する

シャットダウン後に電源を入れ、ターミナルで次を実行する。

sysctl kern.boottime

表示される起動時刻が、電源を入れた直後の時刻になっていれば、カーネルが一から起動し直されている。

5.3 付随する設定（任意）

Mac で「前回の状態が残る」と感じる原因は、プロセスの生き残りではなく、アプリとウインドウの復元機能であることが多い。これを抑えると、毎回まっさらな状態で始まる。

  1. シャットダウンを選ぶと出る確認ダイアログで、「再度ログインしたときにウインドウを再度開く」のチェックを外してから、「システム終了」を押す。
  2. 恒久的にしたい場合は、「システム設定」→「デスクトップと Dock 」を開き、「ウインドウ」の項目にある「アプリケーションを終了するときにウインドウを閉じる」をオンにする。
  3. 「システム設定」→「一般」→「ログイン項目と機能拡張」で、ログイン時に自動で開くアプリを必要なものだけに絞る。
蓋を閉じる操作やスリープは、シャットダウンではない。スリープではメモリの内容が保たれたままになる。「リセットしたい」ときは、必ず「システム終了」または「再起動」を選ぶ。

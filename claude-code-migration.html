Claude Code 環境移植ガイド
――Windows 11 ⇔ Mac

A Checklist for Migrating Claude Code Settings, Credentials and Memory Between Windows 11 and macOS

Claude Code の設定は「ユーザー設定」「プロジェクト設定」「認証」「 MCP サーバー」「 Claude Code 本体のインストール」の 5 系統に分かれている。 CLAUDE.md の上書きコピーは、そのうちの一部（ユーザー記憶）に過ぎない。

以下、優先度の高い順に並べる。

【出典と時点】 Claude Code の設定・記憶を別 PC へ移すためのチェックリストである。 2026 年 10 月時点の公式ドキュメントに基づく（ 2026 年 8 月版から改訂）。

1ユーザーレベル設定（ ~/.claude/ 配下）

全プロジェクト共通で効く、あなた個人の設定である。ホームディレクトリ配下にあるため、これが「移植の本丸」になる。

ファイル / ディレクトリ内容移植方法
~/.claude/CLAUDE.md グローバルなメモリ。プロジェクト横断で常に読み込まれる指示・好み 同じ相対パスにファイルをコピー
~/.claude/settings.json 権限（許可 / 拒否コマンド）、環境変数、モデル既定値などユーザー設定 同じ相対パスにコピー。中身は JSON なのでそのまま持っていける
~/.claude/skills/ 個人用スキル（ skills/<名前>/SKILL.md と付属ファイル）。現在は新規ワークフローの標準的な置き場所 ディレクトリごとコピー
~/.claude/commands/ カスタムスラッシュコマンド（ .md ファイル群）。スキルと同じ仕組みに統合されており、既存ファイルはそのまま動く ディレクトリごとコピー
~/.claude/rules/ 全プロジェクト共通のルール（トピック別の Markdown 。 paths で対象ファイルを絞ることもできる） ディレクトリごとコピー
~/.claude/agents/ カスタムサブエージェント定義 (YAML frontmatter 付き Markdown) ディレクトリごとコピー
~/.claude/workflows/
~/.claude/agent-memory/		 保存した動的ワークフロー(.js)と、サブエージェントの永続メモリ ディレクトリごとコピー
~/.claude/output-styles/ 出力スタイル設定 ディレクトリごとコピー
~/.claude/keybindings.json キーバインドの上書き設定（存在する場合のみ） コピー
~/.claude/themes/ カスタムカラーテーマ（存在する場合のみ） ディレクトリごとコピー
~/.claude/plugins/ インストール済みプラグイン（ installed_plugins.json を含む） コピーより、新 PC でプラグインを入れ直すほうが確実
Windows 11 の実パス
%USERPROFILE%\.claude\
例は C:\Users\あなたの名前\.claude\
macOS の実パス
~/.claude/
例は /Users/あなたの名前/.claude/
フォルダごとコピーする場合の注意
.claude フォルダを丸ごと ZIP 化すると、移植してはいけないものまで含まれる。 設定ファイル類だけを選んでコピーするのが安全である。
  • .credentials.json ： Windows と Linux ではログイン情報がここに平文で保存される（次章参照）。コピーしない
  • projects/ ： 会話の全記録(*.jsonl)が入る。容量が大きく、ファイル内容やコマンド出力も含まれる。 Auto Memory もここにある（第 5 章参照）
  • file-history/ 、 plans/ 、 debug/ 、 shell-snapshots/ 、 backups/ など：セッション中に生成される作業データで、移す必要はない
settings.json 内のパスが OS 依存の値（ C:\... と /Users/... など）を含む場合は、コピー後に中身を確認する。

2認証・ API キー

2.1 ログインセッション (OAuth)

ログイン情報の保存先は OS で異なる。 macOS では暗号化された Keychain 、 Windows では %USERPROFILE%\.claude\.credentials.json 、 Linux では ~/.claude/.credentials.json である。 ~/.claude.json はアプリの状態や個人用 MCP サーバーの置き場で、認証情報の本体ではない。いずれもトークンを直接コピーするのは推奨されない（環境・デバイス依存のため、失効やセキュリティリスクがある）。

新 PC では、ターミナルで claude を起動するとブラウザでのログインが始まる。起動後に /login で再ログインすることもできる。ブラウザが戻らない環境では、画面に出るコードを端末へ貼り付ける。ログアウトは /logout 、状態確認は /status である。

CI など対話ログインのできない環境向けには、 claude setup-token で 1 年有効のトークンを発行し、環境変数 CLAUDE_CODE_OAUTH_TOKEN に設定する方法がある。ただしこのトークンはモデル呼び出し専用で、 claude.ai コネクタなどは使えない。

2.2 API 課金運用の場合

API 直接課金で使っている場合は、 ANTHROPIC_API_KEY 環境変数、または settings.json の env ブロックや apiKeyHelper（外部スクリプトでキーを都度取得する仕組み）を移植する。 ANTHROPIC_API_KEY が設定されていると、初回に使用の可否を尋ねられ、承認するとサブスクリプションのログインよりキーが優先される。サブスクリプションで使う PC には、このキーを残さない。

// settings.json の env ブロック例
{
  "env": {
    "ANTHROPIC_API_KEY": " （新PCでは環境変数側で管理し、ここには書かないのが安全） "
  }
}
API キーそのものをファイルに書いて渡すのは避ける
API キーは OS の環境変数やシークレット管理（ Windows なら「システム環境変数」、 Mac ならシェルの ~/.zshrc 等）に個別設定し、設定ファイルには直接書き込まない運用が安全である。

3プロジェクトレベル設定

各リポジトリ（プロジェクトフォルダ）内にある設定である。 Git リポジトリならクローンするだけで自動的に付いてくる。

ファイルスコープGit 管理
CLAUDE.md
（または .claude/CLAUDE.md ）		 プロジェクト固有の指示。チーム共有 する（コミット対象）
.claude/settings.json チームで共有する権限設定・ MCP 設定など する
.claude/settings.local.json 個人限定の上書き設定（実験用など） しない（ gitignore 対象） - 手動で移植が必要
.claude/rules/ トピック別の指示。対象ファイルを絞ることもできる する
.claude/skills/
.claude/commands/		 プロジェクト専用のスキル・コマンド する
.claude/agents/ プロジェクト専用サブエージェント する
.claude/output-styles/
.claude/workflows/		 チームで共有する出力スタイルと、保存した動的ワークフロー する
.claude/agent-memory/
.claude/agent-memory-local/		 サブエージェントの永続メモリ（ memory: project は前者、 memory: local は後者に書かれる） 前者はする、後者はしない - 後者は手動で移植が必要
CLAUDE.local.md 個人用のプロジェクトメモ。 CLAUDE.md の後に読み込まれる しない - 手動で移植が必要

実質的にやること
Git で管理されているリポジトリなら、新 PC で git clone するだけで大部分は再現される。注意すべきは gitignore 対象になっている個人ファイル(settings.local.json 、 CLAUDE.local.md)で、これらは手動でコピーしない限り引き継がれない。
AGENTS.md を使っているリポジトリ
Claude Code は、作業ディレクトリとその上位に CLAUDE.md も CLAUDE.local.md もない場合に限り、 AGENTS.md を読む。新 PC で CLAUDE.local.md だけを追加コピーすると、 AGENTS.md が読まれなくなることがある。両方を読ませたい場合は、設定の「 Project instructions 」を claude-md-and-agents-md にする。

4MCP サーバー設定

MCP (Model Context Protocol) サーバーの登録先は、スコープによってファイルが異なる。同じサーバーが複数のスコープにあるときは、ローカル、プロジェクト、ユーザーの順に優先され、設定は統合されない。

スコープ保存場所備考
ローカル（既定。個人×プロジェクト） ~/.claude.json 内（そのプロジェクトのパスの下） claude mcp add の既定。認証情報を含むサーバーや試験用に向く。 .claude/settings.local.json とは別物
プロジェクト .mcp.json リポジトリ直下。 Git でチーム共有可能。初回利用時に承認を求められる
ユーザー ~/.claude.json 全プロジェクトで使う個人用サーバー(--scope user)。アプリの状態や UI 設定も同居
再登録という選択肢
claude mcp list で現在登録されている MCP サーバー一覧を確認し、新 PC 側で claude mcp add を使って再登録するほうが、認証まわりのトラブルが少なく確実である。設定ファイルを直接コピーする場合は、サーバーによっては個別の認証（トークンなど）が別途必要になることがある。 OAuth が必要なサーバーは、登録後に /mcp または claude mcp login <名前> で認証する。
claude.ai コネクタは移植不要
claude.ai のコネクタ設定で追加した MCP サーバーは、 claude.ai アカウントでログインすると Claude Code にも自動で現れる（ /mcp では「 claude.ai 名前」と表示）。 API キーや apiKeyHelper 、クラウドプロバイダ経由で使う場合は読み込まれない。 Gmail や Google Calendar など一部のコネクタは、ローカルの OAuth に対応しておらず、 claude.ai 側での接続が必要である。

5Auto Memory （自動記憶）――見落としやすいポイント

Auto Memory はマシンローカルで、原則「移植されない」
Claude Code には、ユーザーが書く CLAUDE.md とは別に、 Claude が会話中に自動で学習内容を書き留める「 Auto Memory 」機能がある（デフォルトは ON ）。保存先は リポジトリごと・マシンごと に分かれており、 ~/.claude/projects/<プロジェクト名>/memory/ に置かれる（同じリポジトリの worktree やサブディレクトリでは共有される）。中心は MEMORY.md で、起動時に先頭 200 行または 25KB までが読み込まれ、長くなるとトピック別のファイルに分かれる。この機能はローカルの学習内容であり、他の PC へは自動的に引き継がれない。重要な決定事項が書かれていた場合は、内容を確認してプロジェクトの CLAUDE.md など永続的なファイルへ手動で書き写すことが推奨される。

セッション中に /memory コマンドを実行すると、 CLAUDE.md ・ CLAUDE.local.md ・ Auto Memory の場所を一覧表示でき、 Auto Memory の ON / OFF の切り替えや保存フォルダを開く操作もできる。実際に読み込まれたファイルは /context の「 Memory files 」で確認できる。移植前に新旧環境で見比べると確実である。

保存先を変えたい場合は、 settings.json の autoMemoryDirectory で指定できる。

6前提環境（ Claude Code 本体のインストール）

  • ネイティブインストーラーが推奨である。 Windows (PowerShell) は irm https://claude.ai/install.ps1 | iex 、 macOS ・ Linux ・ WSL は curl -fsSL https://claude.ai/install.sh | bash を実行する。 Node.js は不要で、バックグラウンドで自動更新される
  • パッケージマネージャ経由も選べる： Mac は brew install --cask claude-code （約 1 週間遅れの stable 版。最新版を追うなら claude-code@latest ）、 Windows は winget install Anthropic.ClaudeCode 。ただしこれらは自動更新されないため、 brew upgrade claude-code や winget upgrade Anthropic.ClaudeCode で定期的に更新する
  • npm 版(npm install -g @anthropic-ai/claude-code)も引き続き使える。 Node.js 22 以降が前提だが、実体はネイティブバイナリで、実行時に Node.js は使わない
  • Windows では Git for Windows は必須ではない。入れると Bash ツールが使え、入れない場合は PowerShell ツールで代替される
  • インストール確認は claude --version 、診断は claude doctor 、手動更新は claude update である
  • シェル補完を設定していた場合は、それぞれの環境向けに再設定する

7移植チェックリスト（実行順）

  1. 新 PC にネイティブインストーラー（または Homebrew / WinGet ）で Claude Code 本体を入れ、 claude --version で確認する
  2. ~/.claude/CLAUDE.md をコピーする (Windows: %USERPROFILE%\.claude\CLAUDE.md ⇔ Mac: ~/.claude/CLAUDE.md)
  3. ~/.claude/settings.json をコピーし、中身のパス・環境変数が OS 依存でないか確認する（ .credentials.json と projects/ はコピーしない）
  4. ~/.claude/skills/ 、 commands/ 、 rules/ 、 agents/ 、 output-styles/ など、使っているものをまとめてコピーする。プラグインは新 PC で入れ直す
  5. 新 PC で claude を起動してブラウザでログインする（または /login ）。トークンの直接コピーはしない
  6. API 課金運用なら、 ANTHROPIC_API_KEY を新 PC の環境変数として設定する
  7. プロジェクトは Git で clone し、 .claude/settings.local.json ・ CLAUDE.local.md があれば個別にコピーする
  8. claude mcp list で登録済み MCP サーバーを確認し、新 PC 側で claude mcp add により再登録する（または .mcp.json をコピーする）。 claude.ai コネクタはログインだけで現れる
  9. 旧 PC で /memory を実行し、 Auto Memory の中に永続化すべき内容がないか確認して、手動で転記する
  10. 新 PC で /status と claude doctor を実行し、設定とログインが正しく読み込まれているか検証する
検証コマンド
移植後は /status（認証方法や設定ソースの確認）や claude doctor（インストールと設定ファイルの診断）、 /context（読み込まれた指示ファイルの一覧）を実行すると、意図した設定が実際に読み込まれているか確認できる。

※ 本稿は 2026 年 10 月時点の公式ドキュメントに基づく実践ガイドであり、 Claude Code の仕様変更により、保存先やコマンド名が変わる可能性がある。

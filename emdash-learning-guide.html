EmDash を学ぶべきか ― WordPress と比べた条件の整理

作成日 : 2026-10-24 ／ 出典の取得日 : 2026-10-24 ／ 本文は取得日の時点の情報に基づく

この記事は、 Cloudflare の CMS 「 EmDash 」について、 WordPress と比べて何がどう違うかを整理し、どのような条件の人にとって学ぶ価値があるかを検討するものである。結論は、調べた事実の範囲で導く。調べていない事項と、報道の食い違いは、末尾の「限界」で述べる。

1. 問いと方法

主題の問いは、 EmDash は WordPress と比べて、どのような条件の人にとって学ぶ価値があるのか、学ぶとすればどの順に何をすればよいのか、である。選択肢は四つ検討する。今 EmDash を学ぶ、 WordPress を続ける、両方を使う、判断を先に延ばす、である。

本文の事実は三つに区分して示す。 確立した事実 は一次情報（公式リポジトリ・公式ドキュメント）で確認したものを指す。 未確定 は二次情報（報道・解説記事）にとどまり、検証が足りないものを指す。 投機 は将来の予測を指す。

2. EmDash の概要

確立した事実 EmDash は、 Cloudflare が公開する MIT ライセンスの CMS （コンテンツ管理システム。 Web サイトの文章や画像を管理する仕組み）である。公式リポジトリは、 EmDash を Astro （ Web サイトを作るための、 TypeScript 製の枠組み）に基づく TypeScript （ JavaScript に型の宣言を加えた言語）の CMS と説明し、 WordPress の「精神的後継」という語を説明文に使っている [1] 。この呼称は提供元の枠組みであり、本記事は事実の評価としては用いない。

未確定 版 1.0 は、 2026 年 9 月 28 日頃に公開されたと報じられている。報道は、ベータを脱した無料の CMS と紹介している [2] 。

確立した事実 公式の移行ガイドは、 0.x の版（ 1.0 より前の版）から 1.0 への移行で「 Removed 」として扱う項目を四つ挙げている [3] 。 その四つは、関数 cloudflareCache()、 emdash/ui からの Comments と CommentForm の書き出し（ emdash/ui/comments からは引き続き使える）、 CLI のコマンド emdash dev と emdash auth secret 、設定の experimental.registry である。 1.0 以後の破壊的変更（既存の利用方法が動かなくなる変更）は、メジャー版（版番号の先頭の数字が変わる版）でのみ行うとリリース情報に書かれている [4] 。

確立した事実 実行環境は、 Cloudflare の Workers （ Cloudflare が提供する、サーバーの管理を要しない実行環境）と D1 （データベース）、 R2 （ファイル保存領域）、または SQLite （小型のデータベース）を使う、 Node.js （サーバー上で JavaScript を動かす実行環境）のサーバーである [1] 。プラグインは Dynamic Worker Loaders （隔離された実行環境を作る Cloudflare の仕組み）と呼ばれる環境で動き、使う能力を宣言するマニフェスト（プラグインが使う能力を宣言する書類）を持つ [1] 。

確立した事実 CLI （ターミナルから操作する道具）と、 MCP サーバー（ AI エージェントが接続して操作する窓口）が標準で組み込まれている [1] 。 MCP の接続先（エンドポイント。通信の届け先）は /_emdash/api/mcp である。認証は Bearer トークン（合言葉に当たる文字列）による。方式は、 OAuth 2.1 （外部のサービスで許可を得る仕組み）、個人アクセストークン、デバイス認可（ターミナルなど、画面の限られた道具で認証する方式）の三つである。操作できる範囲は、スコープ（許可の単位）で絞る [5] 。サイト全体の移転に使うツールは、管理者 (Admin) だけが使える [5] 。

未確定 プラグインの隔離の強度は、実行環境によって異なる可能性がある。報道は、 Cloudflare 上の隔離に有料プランを要すると書く一方、 Node.js 上でも workerd （ Cloudflare の実行環境の基盤）で隔離できると書く。前者は 1.0 より前のレビューの記述である。信頼モードでは宣言が文書上の意味にとどまり、強制されるのはサンドボックスモードのみとする二次情報もある。この二つは食い違っており、本記事は確定しない [6] 。

4. 条件別の向き不向き

以下は、 2 章と 3 章の事実に基づく筆者の判断である。判定の軸は、既存の WordPress 資産への依存、 AI エージェントによる操作の需要、学習に使える時間、提供元と統治の変化を許容できるかの四つである。

読者の条件筆者の判断
既存の WordPress の資産（特定のプラグインやテーマ）に強く依存するWordPress を続けるほうが合理的だと考えられる。移行の費用と、同等の機能の有無を、先に確認する必要がある
新規のサイトで、 AI エージェントによる操作を重視し、提供元と統治の変化を許容できるEmDash は検討に値すると考えられる。 WordPress 側にも 6.9 で AI 連携の仕組みがある。両者の機能の比較は、本記事では行っていない。根拠は、新規のサイトであれば既存の資産を移す費用がかからない点である
既存の資産を持つが、新規の部分を試したい両方を使う選択が妥当と考えられる。新規の部分だけを EmDash で試し、移行は小さく行うのが無理が少ない
TypeScript と Node.js の学習に使える時間がほとんどない今は判断を延ばすか、 WordPress を続けるのが妥当と考えられる

5. 2026 年 10 月から始める道のり

この章は、 4 章の表の 2 行目と 3 行目に当てはまる読者に向けた道のりである。起点は 2026 年 10 月、期間は 6 か月（ 2027 年 3 月まで）、学習時間は週 5 時間を仮定する。これらは筆者の仮定である。各段階の長さと所要時間は、筆者の見積もりであり、合計は約 112 時間となる。
  1. 基礎と説明（ 10 月下旬〜 11 月中旬、約 15 時間と見積もる）。 目標は、 EmDash と WordPress の構成の違いを説明できることである。ターミナルの操作、 Node.js （サーバー上で JavaScript を動かす実行環境）、 TypeScript （ JavaScript に型の宣言を加えた言語）の読み方を学ぶ。終わりに、構成図と説明文を一つずつ作る。これで説明できるかを確かめる。
  2. 構築（ 11 月中旬〜 1 月上旬、約 35 時間と見積もる）。 目標は、検証用のサイトを手元で動かし、公開することである。 Node.js の版の要件は、二次情報の間で食い違う。公式のはじめ方ページは、 Node.js 22.23.4 以上を求めている [18] 。古い二次情報には 22.12 以上や 22.16 以上とするものもあるが、公式の記述を優先する。終わりに、公開した検証サイトを示す。
  3. 移行（ 1 月、約 20 時間と見積もる）。 小さな WordPress サイトを試しに移行し、移ったものと移らなかったものを表にする。終わりに差分表を作る。
  4. 拡張（ 2 月、約 20 時間と見積もる）。 プラグインか MCP のどちらか一方を選ぶ。 MCP は、個人アクセストークンか、スコープを絞った OAuth で認証する。終わりに、動作した手順を記録する。
  5. 運用（ 3 月、約 22 時間と見積もる）。 版の更新、バックアップと復元、権限の設計を手順にする。終わりに、一度の更新と一度の復元を記録する。

学習を続けるかどうかは、 7 章の基準で判断することを提案する。

6. 学習資料の評価

学習の一次資料は、公式リポジトリ [1] と公式ドキュメントの MCP のリファレンス [5] である。 EmDash の専用書籍は、確認できなかった。確認できた書籍は、技術評論社の『 Cloudflare Workers 実践ガイド―エッジで実現する Web アプリケーションの設計・実装・運用』（ 2026 年 5 月発売）である [19] 。 Workers 、 D1 、 KV （ Workers の鍵と値の保存領域）、 R2 、 Durable Objects （状態を保つ仕組み）を扱う、周辺技術の資料と位置づける。事前のメモの記載では、この書籍は EmDash に言及していない。 EmDash への言及の有無と目次は、確認していない。事前のメモに挙がっていた書籍『図解 Cloudflare とは何か』と動画講座『これから始める EmDash 入門』は、検索で見つからなかったため、本記事では扱わない。

7. 見直しの基準

次のいずれかに該当した場合は、 4 章の判断と 5 章の道のりを見直すことを提案する。 2027 年 3 月までに、新しい版が 3 か月以上出ない。提供元の方針が変わり、ライセンスや提供形態が変わる。 5 章の構築か移行の段階が、見積もりの 1.5 倍を超えて遅れる。見直しの結果、撤退も選択肢とする。判断を延ばした読者は、提供元製のプラグインが 1.x の版に達すること、有料プランの要否と隔離の強度が公式文書で確定することを、再判断の条件とすることを提案する。 WordPress を続けた読者も、統治をめぐる報道（時期の記述は報道により異なる）が確定した時点で、判断を見直すことを提案する。

投機 EmDash が今後どの程度普及するかは、本記事の調査では判断できない。普及の見通しを、本記事は判定の根拠に使わない。

8. 限界

本記事は、二次情報に頼る部分がある。 WordPress 側のプラグインの品質は、本記事では調べていない。提供元と統治の状況は、二次情報のみで確認した。 Node.js の版の要件は公式のはじめ方ページで確認した。これと異なる二次情報もある。 Cloudflare の有料プランの要否と隔離の強度は、報道の記述が食い違い、確定していない。プラグインの件数、脆弱性の割合、統治の時期、利用シェアの計測の差も、資料により食い違う。道のりは実機で検証していない。所要時間と学習時間は、筆者の仮定と見積もりである。日付は 2026 年 10 月 24 日時点である。
